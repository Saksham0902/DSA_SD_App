Three reflexes from this app

    Expand right, shrink left

    Variable-size windows for “longest” and “shortest” contiguous answers. One loop, two pointers, each index touched twice at most.

    The caterpillar

    A window is a contiguous slice [l, r]. The right edge always moves forward, eating the next element. If that breaks the rule (a repeated letter, too many distinct values), the left edge crawls forward until the rule holds again. Then you record the answer.

    Brute force tries every (l, r) pair: O(n²). The caterpillar never moves backward, so it's O(n).

    Fixed windows & the deque

    When the size is given, add one and drop one. When you need the max of every window, keep a monotonic deque.

    Add one, drop one

    With a fixed size k, there's nothing to decide about shrinking: every step adds nums[r] and removes nums[r − k]. Keep a running sum or a running count, and never recompute the window from scratch.

    Counting the cost

    A while inside a for that is still O(n): amortised counting.

    How to price a sliding-window solution

    1. Don't multiply the loops. A while that shrinks the window inside a for that grows it looks like O(n²).
    2. Count entries and exits instead. Each index enters the window once (right moves) and leaves at most once (left moves). Total ≤ 2n → O(n).
    3. Space is whatever describes the window: a count map is O(distinct items in the window), bounded by the alphabet (O(26) = O(1) for lowercase letters).
