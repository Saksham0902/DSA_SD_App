    Recursion that remembers

    DP isn't a new algorithm. It's the recursion you already know, plus a notebook so you never solve the same subproblem twice.

    Four versions of the same idea

    Climbing Stairs: one or two steps at a time, how many ways to reach step n? The last move was either 1 step (from n − 1) or 2 steps (from n − 2), so ways(n) = ways(n − 1) + ways(n − 2). Write that as recursion and it works, but it recomputes the same values exponentially often.

    Add a cache and it's O(n). Flip it into a loop that fills a table from small to large and you have bottom-up DP. Notice each value only needs the last two, and the table shrinks to two variables. Same recurrence, four costumes.

    The recipe

    1. State: what does dp[i] mean?Write it as a full sentence: “dp[i] = the best I can do using the first i houses”.
    2. Recurrence: how does dp[i] use smaller states?Ask “what was the last decision?” Each option points to a smaller state.
    3. Base cases: the smallest states.Usually dp[0], sometimes the first row and column.
    4. Order: fill so inputs are ready.If dp[i] reads dp[i − 1], go left to right. Then optimize space if only a few previous values are read.
    2

    1-D patterns

    A handful of shapes cover most one-dimensional DP: take or skip, best way to reach an amount, best run ending here.

    What was the last decision?

    House Robber: at house i you either skip it (keep dp[i − 1]) or rob it (dp[i − 2] plus its money). Coin Change: the last coin used was one of the coins, so dp[a] looks at dp[a − c] for every coin. LIS: the run ending at i extended some earlier run ending at j. Every 1-D recurrence comes from listing the possible last moves.

    2-D tables

    Two strings, a grid, or items × capacity. The table is a map of subproblems, and each cell reads its neighbours.

    Prefixes against prefixes

    For two strings, let dp[i][j] describe the first i characters of one against the first j of the other. Then only the last characters matter: if they match, extend the diagonal; if not, try dropping one character from either side. Size the table (m + 1) × (n + 1) so the empty prefix is row 0 and column 0.

    ⏱

    Counting the cost

    States × work per state. That’s the whole formula.

    How to price a DP solution

    1. Count the states: the size of the table (or of the memo dict). 1-D over n → n states; 2-D over m × n → m·n.
    2. Count the work per state: how many earlier states one cell looks at. Climbing stairs: 2 → O(1). LIS: all earlier j → O(n).
    3. Time = states × work per state. Space = the table, often shrinkable to one or two rows when each row only reads the previous one.
    4. Compare with plain recursion: same states, recomputed exponentially many times.
