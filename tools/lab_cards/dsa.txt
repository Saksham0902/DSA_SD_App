# Problem cards for the DSA labs. Format: see build.py. Each example answer must match the lab's last step.

== hashing.html lab-hash
-- two | LeetCode 1
P: You get a list of numbers and a target. Return the indexes of the two numbers that add up to the target.
E: `nums = [3, 8, 5, 1, 7]`, `target = 12` → `[2, 4]`, because 5 + 7 = 12.
I: For each number x, the partner it needs is `target − x`. Instead of a second loop to look for it, ask a dict of the numbers already passed. That lookup is O(1), so one pass is enough.
S: (cur){▲i} the number being checked
S: (on) numbers already passed, now stored in the dict
S: (ok) the two numbers that add up to the target
S: {seen} the dict: value → index

-- dup | LeetCode 217
P: Return true if any number appears more than once in the list, and false if every number is different.
E: `nums = [4, 1, 7, 3, 1]` → `true`, because 1 appears twice.
I: Keep a set of the numbers seen so far. Before adding a number, check whether it is already in the set.
S: (cur){▲x} the number being checked
S: (on) numbers already added to the set
S: (bad) the repeat: it was already in the set
S: (ok) where that number first appeared
S: {seen} the set

-- run | LeetCode 128
P: Find the length of the longest run of consecutive numbers (like 1, 2, 3, 4) that you can make from the list. The numbers can be in any order.
E: `nums = [100, 4, 200, 1, 3, 2]` → `4`, from the run 1, 2, 3, 4.
I: Put every number in a set. Only start counting at x when `x − 1` is not in the set, because then x is the smallest number of its run. Count upward with set lookups. Each number is counted once, so the whole thing is O(n).
S: (cur) the number being tried as the start of a run
S: (ok) numbers found while counting upward from that start
S: (dim) skipped: `x − 1` exists, so x is in the middle of a run
S: {best so far}{current run} the longest run found, and the length of the one being counted

== hashing.html lab-prefix
-- sk | LeetCode 560
P: Count how many subarrays (unbroken stretches of the list) add up to exactly k. The numbers can be negative.
E: `nums = [1, 2, −1, 2, 1, −2, 3]`, `k = 3` → `6` subarrays, for example [1, 2], [2, 1] and [3].
I: Keep a running sum. A subarray ending here adds up to k exactly when some earlier running sum equals `running − k`. A dict counts how often each running sum has appeared, so each step is one lookup.
S: (cur) the number just added to the running sum
S: (win) a subarray that adds up to k, found at this step
S: {Σ} under each number: the running sum up to that index
S: {running}{need}{count} the running sum, the earlier sum we look for (`running − k`), and subarrays found so far
S: {seen} each running sum seen so far → how many times

-- pr | LeetCode 238
P: Return a list where each position holds the product of all the other numbers. You can't use division.
E: `nums = [1, 2, 3, 4]` → `[24, 12, 8, 6]`. For example, 24 = 2 × 3 × 4.
I: Each answer is (product of everything to its left) × (product of everything to its right). A left-to-right pass writes the left products; a right-to-left pass multiplies in the right products.
S: (cur) the position being worked on
S: (win) the numbers being multiplied in: everything to its left on the first pass, everything to its right on the second
S: (on) the answer cell being written
S: (ok) the finished answer
S: {left}{right} the running product of everything to the left, and to the right

== two-pointers.html lab-conv
-- two | LeetCode 167
P: The list is sorted. Find the two numbers that add up to the target, and return their positions counting from 1.
E: `nums = [1, 3, 4, 6, 8, 11]`, `target = 10` → `[3, 4]`, because 4 + 6 = 10.
I: Start with the smallest and the largest. If the sum is too big, the largest number can't be in any answer, so move r left. If it's too small, move l right. Every step rules out one number.
S: (cur){▲l}{▲r} the two numbers being added
S: (dim) numbers ruled out: they can't be part of the answer
S: (ok) the pair that hits the target
S: {l + r}{target} the current sum, and the target

-- box | LeetCode 11
P: Each number is the height of a vertical line. Pick two lines that hold the most water between them. The water's area is the shorter line's height × the distance between the lines.
E: `height = [1, 8, 6, 2, 5, 4, 8, 3, 7]` → `49`: the lines at index 1 (height 8) and index 8 (height 7) are 7 apart, and 7 × 7 = 49.
I: Start with the widest pair. The shorter line limits the area, and moving the taller line inward can only make things worse. So always move the shorter line.
S: (cur){▲l}{▲r} the two lines being measured
S: (win) the width between them
S: {area}{best} this container's area, and the best so far

-- 3s | LeetCode 15
P: Find every different group of three numbers that adds up to 0.
E: `nums = [−1, 0, 1, 2, −1, −4]` → `[[−1, −1, 2], [−1, 0, 1]]`
I: Sort the list. Fix one number at i, then use two pointers on the rest to find two numbers that cancel it out. Skip repeated values so the same triple is never listed twice.
S: (hot){▲i} the fixed first number
S: (cur){▲l}{▲r} the two pointers searching the rest
S: (ok) a triple that adds up to 0
S: {res} the triples found so far

-- tr | LeetCode 42

E: `height = [0,1,0,2,1,0,1,3,2,1,2,1]` → `6` units.
I: The water above a bar is `min(tallest bar to its left, tallest bar to its right) − its height`. Two pointers walk inward from the lower side, because the lower side's tallest bar is the one that limits the water.
S: (cur){▲l}{▲r} the two pointers
S: (ok) bars already settled; the number under a bar is the water above it
S: {lmax}{rmax} the tallest bar seen so far from the left, and from the right
S: {water} total water so far

== greedy-intervals.html lab-greedy
-- j1 | LeetCode 55
P: Each number is the longest jump you can make from that index. You start at index 0. Can you reach the last index?
E: `nums = [2, 3, 1, 1, 4]` → `true`: jump from index 0 to 1, then from 1 to the end.
I: Don't try jump combinations. Keep one number, `reach`: the farthest index you can get to so far. At each index i, update it to `max(reach, i + nums[i])`. If i is ever past reach, you're stuck.
S: (cur){▲i} the index being checked
S: (win) indexes you can already reach
S: {▲reach}{reach} the farthest index you can reach so far

-- j2 | LeetCode 45
P: Same jumps as Jump Game, and the last index can always be reached. What is the fewest number of jumps to get there?
E: `nums = [2, 3, 1, 1, 4]` → `2` jumps: index 0 → 1 → 4.
I: Think in levels, like BFS. While you scan the indexes one jump can reach, track the farthest index the next jump could reach. When i reaches the end of the level, take a jump: the next level runs up to that farthest index.
S: (win) the current level: indexes reachable with this many jumps
S: (cur){▲i} the index being scanned
S: {▲end} the last index of the current level
S: {▲far}{far} the farthest index the next jump can reach
S: {jumps} jumps taken so far

-- gs | LeetCode 134
P: Gas stations sit on a circle. At station i you can fill up `gas[i]`, and driving to the next station uses `cost[i]`. You start with an empty tank. Which station can you start from to drive all the way around?
E: `gas = [1,2,3,4,5]`, `cost = [3,4,5,1,2]` → start at station `3`.
I: If the total gas is at least the total cost, some start works. Drive from a candidate start and add each station's gain. If the tank drops below 0 at station i, no station from the start up to i can work, so try i + 1 next.
S: {gain} row: `gas[i] − cost[i]`, how the tank changes at each station
S: (cur){▲i} the station being driven through
S: {▲start} the current candidate start
S: (bad) where the tank went below 0
S: (dim) stations ruled out as a start
S: {tank}{total gain} fuel in the tank now, and the sum of all gains (0 or more means some start works)

-- kd | LeetCode 53
P: Find the subarray (an unbroken stretch of the list) with the largest sum, and return that sum.
E: `nums = [−2, 1, −3, 4, −1, 2, 1, −5, 4]` → `6`, from `[4, −1, 2, 1]`.
I: Walk once, keeping `cur`: the best sum of a run that ends at i. If the run so far is negative, it can only hurt, so drop it and start fresh at `nums[i]`. Remember the best `cur` ever seen.
S: (win){▲i} the current run, which ends at i
S: (ok) the best subarray
S: {cur}{best} the current run's sum, and the best sum so far

== sliding-window.html lab-var
-- lu | LeetCode 3
P: Find the length of the longest stretch of the string in which no character repeats.
E: `s = "abcabcbb"` → `3`, from "abc".
I: Grow the window by moving r one character to the right. If the new character is already inside the window, shrink it from the left until it isn't. Each character enters and leaves the window at most once, so the whole scan is O(n).
S: (win){▲l}{▲r} the window: the stretch being checked
S: (cur) the character just added on the right
S: (bad) a character that's already in the window, so the window has to shrink
S: (dim) characters that have left the window
S: {window}{best} the window's length, and the longest valid one so far
S: {window (set)} the characters inside the window

-- ml | LeetCode 209
P: Find the length of the shortest subarray whose sum is at least the target. Return 0 if there is none.
E: `nums = [2, 3, 1, 2, 4, 3]`, `target = 7` → `2`, from [4, 3].
I: Move r right until the sum reaches the target. Then record the length and move l right, shrinking while the sum still reaches the target. All the numbers are positive, so shrinking always lowers the sum.
S: (win){▲l}{▲r} the window
S: (cur) the number just added on the right
S: (dim) numbers that have left the window
S: {window sum}{target}{best} the window's sum, the target, and the shortest valid length so far

-- cr | LeetCode 424
P: You may change up to k letters of the string into any other letter. How long is the longest stretch you can make where every letter is the same?
E: `s = "AABABBA"`, `k = 1` → `4`, for example "AABA" with its B changed to A.
I: A window works when `window length − (count of its most common letter) ≤ k`: the other letters are the ones you'd change. Grow from the right; when the window breaks that rule, slide the left edge in by one.
S: (win){▲l}{▲r} the window
S: (cur) the letter just added on the right
S: (dim) letters that have left the window
S: {window − maxf}{k} letters this window would need changed, and how many changes you're allowed
S: {best} the longest window that worked so far
S: {count in window} how often each letter appears in the window

== hashing.html lab-cost
-- pairs
M: cost
P: Two ways to find a pair that adds up to a target: nested loops that try every pair, or one pass that looks up each partner in a dict. Both run on bigger and bigger inputs, and every step is counted.
I: The × numbers. Nested loops grow ×4 each time n doubles, which is O(n²); the dict pass grows ×2, which is O(n). At n = 8,000 that's 32 million steps against 8,000.
S: @dbl

-- keys
M: cost
P: Grouping 1,000 words by anagram needs a key for each word: its letters sorted, or a count of each letter. Here the word length k doubles on each run.
I: The sorted key grows a bit faster than ×2 (O(k log k) per word); the count key grows ×2 at most (O(k)). With short words the two are close, so mention both in an interview.
S: @dbl

== two-pointers.html lab-cost
-- moves
M: cost
P: How many pointer moves does a two-pointer pair search make on a sorted list of n numbers?
I: Each move brings L and R one step closer, and neither ever moves back. So there are at most n − 1 moves: O(n) time and O(1) space, whatever the input.
S: (cur){▲L}{▲R} the two pointers on the sorted list; the target is 24

-- dbl
M: cost
P: Pair sum three ways: check every pair, sort and then use two pointers, or use two pointers on a list that's already sorted.
I: All pairs grows ×4 per doubling (O(n²)). Two pointers on sorted input grows ×2 (O(n)). On unsorted input the sort dominates: a bit over ×2 (O(n log n)).
S: @dbl

-- 3sum
M: cost
P: 3Sum two ways: try every triple, or sort, fix one number and use two pointers on the rest.
I: The triple loop grows ×8 per doubling (O(n³)). Fix-one plus two pointers grows ×4 (O(n²)): n fixed numbers, each followed by an O(n) scan. The sort is only O(n log n), so it doesn't change the total.
S: @dbl
