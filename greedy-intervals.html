    Take the best move, never look back

    Greedy algorithms commit to the locally best choice. They're short and fast, but only correct when you can argue the choice never hurts later.

    Greedy needs a reason

    A greedy algorithm makes one irreversible choice per step: take the farthest reach, drop a negative prefix, pick the meeting that ends first. That's why it's O(n) or O(n log n) instead of exploring every option like DP or backtracking.

    The catch: greedy is often wrong. Before trusting it, have a one-line reason, usually “any optimal answer can be swapped to include my choice without getting worse”. No reason? Reach for DP.

    Intervals

    Sort, then sweep. The only real decision is whether to sort by start or by end.

    Sort by start to merge, by end to schedule

    Merging overlapping intervals: sort by start, then each interval either extends the last merged one or starts a new one. Keeping as many as possible (or removing the fewest, or shooting the fewest arrows): sort by end and keep whatever finishes first, because it leaves the most room for everything after.

    Counting the cost

    The sort costs more than the greedy itself.

    How to price a greedy / interval solution

    1. Find the sort. Almost every interval problem starts by sorting by start or end: O(n log n).
    2. Price the scan. One pass deciding merge/skip/count is O(n).
    3. Add the heap if there is one (meeting rooms, scheduling): one push and pop per interval → O(n log n).
    4. Total = the biggest piece, usually the sort. Space: the output list, or the heap: O(n).
