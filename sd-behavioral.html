The idea you'll own

Three reflexes from this topic

    1

    Swap & notify

    Strategy, Observer and Command. Build each diagram step by step; notice they share one skeleton.

    What changes, for behavioural patterns?

    The algorithm(pricing, routing, sorting) → Strategy
    Who reactsto an event → Observer
    When / whetheran action runs (undo, queue, log) → Command
    The modethe object is in → State
    Which checksa request passes → Chain of Responsibility
    One stepof a fixed algorithm → Template Method
    How a collection is walked→ Iterator; who talks to whom → Mediator; restoring old state → Memento

    Strategy: the algorithm is a swappable object

    Analogy: Google Maps asks “car, bike or walk?” The route-finding job stays the same; the algorithm is swapped. If you did the OCP lab on the SOLID page, you've already built this diagram.

    Observer: one change, many listeners

    Analogy: a YouTube channel. You subscribe once; every new video notifies you. The channel doesn't know who you are or what you'll do. Same skeleton as Strategy, but the context holds a list and calls all of them.

    Command: an action becomes an object

    Analogy: a waiter's order slip. The slip can be queued in the kitchen, cancelled, or replayed, because the request is written down as a thing. Memento is its partner: a saved snapshot you can go back to.

    Watch them run

    The diagrams show the classes. This lab shows the objects in action: a fan-out, an undo stack, a state machine and a chain of checks.

    2

    Flow & state

    State, Chain of Responsibility, Template Method, Iterator and Mediator.

    State: each mode is a class

    Analogy: a traffic light. Pressing the pedestrian button means different things on red and on green. Instead of an if (state == …) in every method, each state is a class that knows what's allowed and which state comes next.

    Chain of Responsibility: a line of handlers

    Analogy: airport security. ID check, then baggage scan, then body scan; any one can stop you. Each handler knows only the next one.

    Template Method, Iterator, Mediator

    Template Method: a recipe with one blank (“parse the file”). Iterator: a remote control's “next channel” without knowing how channels are stored. Mediator: an air-traffic tower; planes talk to the tower, never to each other.
