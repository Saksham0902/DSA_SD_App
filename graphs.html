Three reflexes from this app

    1

    Traverse anything

    Grids, networks and dependency lists are all graphs. Learn to see the nodes and edges, then BFS or DFS does the rest.

    A grid is a graph in disguise

    Every cell is a node. Its up, down, left and right neighbours are its edges. “Count the islands” is “count connected components”, and “minimum steps to reach the exit” is “shortest path”. You don't need to build an adjacency list; the grid already is one.

    Wide or deep?

    BFS explores in rings: everything 1 step away, then everything 2 steps away. That makes it the shortest-path tool for unweighted graphs. DFS dives down one path to the end before backing up: perfect for exploring, counting, cycle detection and anything recursive. Both visit every node and edge once: O(V + E).

    2

    Order & groups

    Topological sort orders tasks with dependencies. Union-find tracks which nodes are connected as edges arrive.

    Take what has no prerequisites left

    Courses with prerequisites form a directed graph. A course is ready when all of its prerequisites are done, that is, when its in-degree drops to 0. Kahn's algorithm keeps a queue of ready courses, takes one, and lowers the in-degree of everything it unlocks. If some courses never become ready, they're stuck in a cycle.

    Union-find: who's in my group?

    Each node points to a parent; following parents leads to the group's representative (the root). find walks to the root, union hangs one root under the other. If two nodes already share a root, the new edge connects nothing new: it closes a cycle.

    3

    Shortest paths & spanning trees

    Weighted edges need more than BFS. Dijkstra, Bellman-Ford with a stop limit, and Prim's minimum spanning tree.

    Settle the closest node first

    With weights, the node that's fewest edges away isn't necessarily the closest. Dijkstra keeps a min-heap of (distance, node). The node popped first has the smallest known distance, and with non-negative weights nothing later can beat it, so it's settled. Relax its edges and repeat.

    ⏱

    Counting the cost

    Every vertex once, every edge once: O(V + E).

    How to price a graph traversal

    1. Each vertex is visited once (the visited set guarantees it) → O(V).
    2. Each edge is looked at once from each end (twice if undirected) when you scan neighbour lists → O(E).
    3. Add them, don't multiply: BFS/DFS/topological sort are O(V + E). For a grid, V = R·C and E ≈ 4·R·C → O(R·C).
    4. Priority queues add a log: Dijkstra is O((V + E) log V). Space: visited + queue/stack → O(V).
