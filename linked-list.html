    Pointer surgery

    Rewire nodes without losing any. Save before you cut, use a dummy head, and draw the arrows before you code them.

    Save, then cut

    A linked list node only knows its next. The moment you overwrite curr.next, the rest of the list is unreachable unless you saved it first. Every list bug is a variation of that. So the rhythm is always: save what you're about to lose, rewire, then step.

    Fast & slow

    Two pointers at different speeds find the middle, detect cycles and locate where the cycle starts, all in O(1) memory.

    The tortoise and the hare

    Move slow one step and fast two. When fast hits the end, slow is in the middle. If there's a cycle, fast never hits the end; it laps slow and they meet inside the loop. No visited set required.

    Counting the cost

    Count hops along the list, and watch out for recursion’s hidden stack.

    How to price a linked-list solution

    1. Count hops. One walk to the end is n hops → O(n). There's no random access, so “get the k-th node” is O(k).
    2. Fast and slow pointers: fast takes 2 hops per round, so the loop runs about n/2 times → still O(n), with O(1) space.
    3. Recursion on a list (reverse, merge) uses one stack frame per node → O(n) space. The iterative version is O(1).
