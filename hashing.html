    Have I seen this before?

    The question behind most array problems, and the data structure that answers it in O(1).

    Memory buys time

    The brute force for “find two numbers that add to a target” checks every pair: for each element, scan everything before it. That inner scan is asking one question over and over: is the partner somewhere behind me?

    A dict answers that question in O(1). Walk the array once, and before moving on, write down what you saw. Now the inner loop is a lookup, and O(n²) becomes O(n), paid for with O(n) memory.

    Canonical keys

    “Group the anagrams” sounds like comparing every pair of words. Instead, give each word a canonical form that's identical for all its anagrams, and let a dict do the grouping. Sorted letters work; a tuple of 26 letter counts works in O(k) per word.

    2

    Prefix sums

    Precompute running totals once, and any range sum becomes one subtraction. Then combine with a dict for the famous “subarray sums to k”.

    Running totals

    Let pre[i] be the sum of the first i elements, with pre[0] = 0. Then the sum of nums[l..r] is pre[r + 1] − pre[l]: everything up to r, minus everything before l. One O(n) pass buys O(1) answers forever.

    Matrix moves & the full set

    In-place matrix tricks interviewers love, then every problem in this topic worth practicing.

    Decompose the move

    Matrix problems look fiddly because you try to do the whole transformation at once. Break it into simple moves you can do in place: a rotation is a transpose plus a mirror, a spiral is four edges with shrinking walls, and “set zeroes” stores its flags in the matrix's own first row and column.

    Counting the cost

    Why a dict turns O(n²) into O(n), and what it costs in memory.

    How to price a hashing solution

    1. Count passes over the input. One loop over n items is O(n). A loop inside a loop over the same items is O(n²).
    2. Price each dict/set operation at O(1) on average. (Worst case O(n) if everything collides; say “average” out loud.)
    3. Add the cost of building keys. Sorting a word of length k for a key is O(k log k); a 26-count tuple is O(k).
    4. Space is the size of the dict: up to n entries → O(n). That’s the trade: memory for speed.
